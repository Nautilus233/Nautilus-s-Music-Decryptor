# 音乐解密工具 · Music Decryptor

本地优先（离线可用）的音乐解密工具：离线解密 **网易云 `.ncm`**、**QQ 音乐 QMC/MGG/MFLAC** 等加密格式；
遇到必须联网/硬件绑定的新格式时，**自动切换**到“备用搜索 - 下载安全音源”流程。
可打包为一个带自定义图标的独立 `MusicDecryptor.exe`。

> ⚠️ **仅限个人本地研究**：只处理你本机已有的加密文件或你自己的备份。
> 本项目**不含任何音频内容**，不绕过平台付费/授权。请遵守当地法律与平台条款，勿传播版权内容。
> 完整设计见 [DESIGN.md](DESIGN.md)。

---

## 特性

- **离线优先**：NCM、QMC0/QMC3/QMCflac/QMCogg 等完全离线解密，无需联网、无付费 API。
- **自动降级**：新版 QQ 音乐 `STag`（文件内无密钥）自动标记“需联网破解”，立即转备用下载。
- **备用下载**：内置酷我 / 酷狗 / 全网聚合（MyFreeMP3 风格）/ 本地曲库音源；可配置顺序。
- **下载即校验**：按**真实文件头**判定格式，校验码率/大小，拦截错误页与低质文件。
- **稳**：超时 + 重试，逐源切换，单文件失败不影响整批；SHA-256 去重避免重复劳动。
- **元数据**：保留并写回标题/艺术家/专辑/封面；缺失时用搜索结果补齐（可关）。
- **美观 GUI**：拖拽、批量、音质筛选、进度条、彩色状态、实时日志。
- **零原生依赖**：AES/TEA 纯 Python 实现（无 `pycryptodome`），网络层用标准库（无 `requests`）。

## 支持格式

| 平台 | 扩展名 | 离线 |
|---|---|---|
| 网易云 | `.ncm` | ✅ |
| QQ 音乐 QMCv1 | `.bkcmp3 .bkcm4a .bkcflac .bkcwav .bkcape .bkcogg .bkcwma .tkm` | ✅ |
| QQ 音乐 QMCv2 | `.qmc0 .qmc2 .qmc3 .qmc4 .qmc6 .qmc8 .qmcflac .qmcogg` | ✅（有内嵌密钥时）|
| QQ 音乐 MGG/MFLAC | `.mgg .mgg0 .mgg1 .mggl .mflac .mflac0 .mmp4` | ✅ `QTag`；❌ `STag`（转备用下载）|
| 已是明文 | `.mp3 .flac .ogg .m4a .aac .wav .ape .wma .dff` | 直接复制 |

## 安装

需要 **Python 3.10+**（开发验证于 3.14）与 Windows 10/11。

```powershell
python -m pip install -r requirements.txt
```

## 使用

```powershell
python main.py                 # 启动图形界面（拖拽 / 批量）
python main.py --cli "D:\in"   # 无界面批处理
python main.py --cli a.ncm --output D:\out --quality flac
python main.py --check-qt      # 自检：确认 Qt 能加载（界面无法启动时先跑这个）
python main.py --check-ui      # 自检：主窗口与设置弹窗是否在本机屏幕上完整可见
python main.py --selftest      # 运行自检
python main.py song.ncm --auto # 启动后立即开始
```

图形界面：添加文件/文件夹（或拖入）→ 选音质（默认 MP3）→ `开始解密` → 看列表与日志。

**输出位置**：默认写到**源文件所在目录**（不再落到 exe 自己的 `dist\` 目录）；同名会加 `(1)`，绝不覆盖源文件。可在界面上手动指定其它输出目录。窗口会按当前屏幕工作区自适应，底部按钮不会被任务栏遮住。

## 疑难排查

- **双击 exe 弹出 `DLL load failed while importing QtCore: 找不到指定的程序`**：
  这是打包机 `PATH` 上存在 **同名但不同版本的 `icuuc.dll`**（例如 Poppler 自带的 ICU）被 PyInstaller 误打包，遮蔽了 Windows 系统 ICU 导致的。
  本仓库的 spec 已修复（过滤掉所有 `icu*.dll`）。若你自行改动打包配置，请保留该过滤；并用 `dist\MusicDecryptor.exe --check-qt` 回归。
- **界面起不来 / 无反应**：先跑 `python main.py --check-qt`；再用 `build\music_decryptor_console.spec` 构建控制台版，让报错直接打到命令行。
- **窗口或设置弹窗底部被屏幕/任务栏挡住**：先跑 `python main.py --check-ui`（或 `dist\MusicDecryptor.exe --check-ui`）。它会按你的屏幕工作区实测主窗口与对话框的几何并给出逐项结论；设置弹窗主体可滚动、`确定/取消` 已固定在底部。
- **某音源没结果**：平台接口会变（反爬/改版），只影响 `mmusic\search\` 下对应文件，可在设置里调整音源顺序或换用聚合网关。

## 备用音源

本地曲库（离线）、酷我、酷狗、全网聚合（MyFreeMP3/NetEase 代理，地址可配置）。

  - 修复 · **带修饰的标题必然让位**：相似度计算会剥掉括号内容，导致「夜曲 (电台版)」与「夜曲」基础分完全相同（都是 1.0）。
    现改为对"多带修饰（括号内容 / 多余词元）"的候选**显式扣分**，干净标题永远排在前面。
  - 修复 · **时长容差 10% → 4.5%（绝对 15s → 10s）**：《夜曲》原曲 3:48、电台版约 3:25，旧容差 ±22.8s 正好放它过关 ——
    这是"下载到电台版"的**直接原因**；新容差 ±10s 会把它排除。
  - 修复 · **原曲时长测量更准**：① 平台标注互相矛盾时自动多测候选（2 → 最多 4 个），避免"前两个恰好都是缩短版"；
    ② 无 Xing 头的 MP3 改为**按真实帧扫描算平均码率**再外推（旧法按首帧码率估，对 VBR 偏差很大）；
    ③ Ogg 与非 faststart 的 m4a 增加**文件尾补探**（这两种容器的时长存在文件末尾）；④ 只要测出 ≥2 个真实时长，
    就以**实测值**为参考，平台标注只作旁证（标注本身可能就是缩短版的）。
- **v1.0.9（备用资源模块 P0 + P1）**
  - 新增 **P0 · 声明式源清单**：源不再是代码里的字典，而是数据（`mmusic/search/pack.py`）。严格白名单 schema
    （未知字段 / 未知 kind / 非 https / 重复 id 一律拒绝），kind 支持 `adapter | json_api | html_scrape | template_url | local`。
    四个内置源已**等价迁移**，行为不变；`registry.py` 改为从清单构建。
  - 新增 **P1 · 资源台账**（`mmusic/search/index.py`，标准库 `sqlite3`）：负缓存（某源对某查询确认无结果/出错后，
    短期内不再重复请求）、资源去重记忆、源健康统计。数据库不可用或关闭时**全部退化为空操作**，绝不阻断任务。
  - 新增 **P1 · 内容去重**（`mmusic/search/fusion.py`）：同一首歌经多个源命中时只保留排名最高的一个，日志写明合并了哪些。
    归一化**刻意保守**（保留括号版本词、只统一大小写与空白），绝不错并用户点名的版本；时长按 2 秒归桶。
  - 新增 `--sources-report`：打印音源清单与健康统计。
  - 新增**依赖红线守卫测试**：断言运行时代码的第三方 import 只有 `PySide6` 与可选 `mutagen`。
  - 说明：台账与哈希缓存共用「启用哈希去重缓存」开关；实测每文件约 10 次台账操作 ≈ 20 ms，相对网络开销可忽略。
- **v1.0.8**
  - 新增：**跨平台参考时长（静默自动）**。参考时长不再采信正在提供文件的平台，而是汇总各音源对同一最佳匹配的标注时长，取「最完整且不离群」的值。实测场景：周杰伦《最长的电影》酷我标注 2:22、酷狗标注 3:55 —— 现在以 3:55 为准，酷我那条被淘汰。
  - 变更：**取消「拿到直链就提前收工」**，改为查询全部音源，否则只看到一个平台的标注，跨平台比对就失效（代价是每个文件多 1~2 次搜索，实测仍在 1~4 秒内）。
  - 收紧：**只下载通过时长验证的资源**。拿到参考时长后，测不出或对不上的候选一律不作为可信选项，宁可如实报「未找到原曲」也不拿没验证过的凑数。
  - 新增：`DJ`/`DJ版` 等改编标记加入排除词；候选自带 `SONGNAME` 等原始字段也会参与版本过滤（实测正是靠它识别出酷我两条「最长的电影」其实是 `(DJ 阿若版)`）。
- **v1.0.7**
  - 明确产品原则：**置信度操作全部静默自动完成**——不弹窗、不要求用户提供参考时长、不新增需要用户配置的开关或阈值；结果提示改为陈述式（`完成（时长未比对）` / `完成（时长存疑）`），不写成要求用户行动的问句。
  - 提速：时长探测候选数 3 → 2，探测超时单独收紧为 8 秒（慢就跳过，不拖慢主流程）；实测单文件（三个在线音源，含搜索/过滤/择优/探测）约 1.0~1.6 秒。
  - 修复：下载失败时不再误报为“只有伴奏/改编版”（前者是源不可用，后者是版本判定，两者已区分开）。
- **v1.0.6**
  - 新增：**时长交叉验证**。下载前对最多 3 个候选只取 256 KB 文件头，解析出**实际音频时长**（FLAC 精确；MP3 走 Xing/VBRI，或按码率估算）；与参考时长偏离超过 `max(15s, 10%)` 的判为可疑版本并**排除**，低于 45 秒的按片段排除。参考时长优先取「最高分候选的平台标注时长」，否则取候选实测时长的最大互认簇。
  - 新增：取不到时长的候选**不作为可信选项**（只在没有可信候选时兜底尝试并警告）；只有一个候选且无法交叉比对时只在结果里陈述式标注（如“完成（单一候选未比对）”）。
  - 新增：**歌名字段硬门槛**——歌名不像就直接淘汰，修掉「同歌手另一首歌（搜“晴天”却收下“花海”）」混进候选的问题。
  - 修复：提前收工改为「最高分候选确实能取到直链」才触发，避免某源无版权时空手而归。
  - 健壮性：MP3 帧只有在带 Xing/VBRI 标签或存在连续第二帧时才被采信（此前 4 KB 随机数据约 86% 会撞出假同步字并算出垃圾时长）；本地音源改用规范的 `file://` URI；`process_file` 统一返回结果而不抛异常。
- **v1.0.5**
  - 新增：**版本过滤**。歌名 / 文件名 / 标签里出现 `伴奏`、`inst`、`remix`、`cover`、`live`、`现场`、`演唱会`、`串烧` 等字样的一律排除，只认原曲；`Alive`、`Instant Crush` 这类正常标题不会误伤。
