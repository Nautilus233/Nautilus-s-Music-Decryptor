# 备用资源获取模块 · 改进方案

> **字体规范声明（遵循 AGENTS.md）**
> 本文档为中文交付文档：标题用 **黑体**，正文用 **微软雅黑**，代码 / JSON 用 **Consolas**；不使用其它字体。
> 文中不含图像识别内容；若遇无法辨认的模糊文字，将原样保留并另行确认，绝不猜测。

> **合规声明**
> 本模块只在**离线破解失败时**作为兜底使用，仅面向**用户本已持有、或合法公开可获得**的音频资源。
> 方案明确**不**绕过登录 / 验证码 / 付费墙，**不**做全站爬取，**不**对第三方内容做 DRM 二次破解，**不**自动采集网盘分享。
> 所有来源以“公开且允许自动化访问”为准入条件，并保留来源与许可元数据以便追溯。

## 0. 目标与边界

### 0.1 要解决的问题

当前备用下载只有少数几个内置源，离线破解失败后命中率偏低。具体表现：

1. **源太少**：单一平台下架、地区限制或反爬时，整首歌就彻底找不到。
2. **直链会过期**：酷我 / 聚合网关返回的是带签名的临时 CDN 链接，缓存后很快失效。
3. **重复劳动**：同一首歌在多个源重复命中，反复下载、反复校验。
4. **冷门歌曲**：歌名变体（feat./Live/翻唱/纯音乐版）导致关键词匹配不到。
5. **源失效无法感知**：接口改版后用户只看到“搜索无结果”，不知道是源坏了。
6. **无法自更新**：源定义写死在代码里，必须等新版本才能修。

### 0.2 明确的非目标（不做的事）

- ❌ 不做无头浏览器（违反零依赖红线，且属于重型方案）。
- ❌ 不自动抓取网盘分享链接（违反多数站点 ToS，且强反爬）。
- ❌ 不绕过登录态 / 验证码 / 付费墙 / DRM。
- ❌ 不从远端下载并执行**代码**（自更新只允许下发**数据**）。
- ❌ 不改变离线解密主路径的性能与稳定性——本模块只在失败分支上工作。

### 0.3 继承的工程约束（AGENTS.md 红线）

- **零依赖**：新增代码只用标准库（`urllib` / `html.parser` / `json` / `sqlite3` / `concurrent.futures` / `hashlib` / `re`）。
- **轻量化**：不引入 Qt 新子模块、不引入新二进制。
- **兼容性第一**：所有网络调用有超时与重试；失败必须有可读提示；不得崩溃。

### 0.4 现状盘点（v1.0.5，避免重复讨论）

以下能力**已经落地**（由 v1.0.4 / v1.0.5 引入），本方案**不重复设计**，只在其上补齐缺口：

- **版本过滤**：`伴奏 / inst / remix / cover / live / 现场 / 演唱会 / 串烧` 等字样一律排除，只认原曲；
  `Alive`、`Instant Crush` 这类正常标题不误伤（`mmusic/match.py`：`version_markers` / `is_original_version` / `split_originals`）。
- **跨音源择优**：所有音源的干净候选**统一排序**，分高者先下、失败顺延；已有 ≥0.95 的高置信度原曲时跳过其余音源以省请求。
- **文件名双读法**：`歌手 - 歌名` 与 `歌名 - 歌手` 都参与打分、取更高分，查询仍只发一次。

**已交付（v1.0.9）**：P0 骨架（`pack.py` 声明式源清单 + `registry.py` 改为清单驱动，内置四源等价迁移、行为不变）与 P1（`index.py` 资源台账：负缓存 / 去重记忆 / 源健康统计；`fusion.py` 内容去重 + 低置信度标记），并附带 `--sources-report` 与依赖红线守卫测试。

仍然缺失、也就是后续阶段要解决的：**源的自更新（P4）、受控并发/限速/熔断（P1 的限速部分）、页面级媒体提取（P2 嗅探）、直链短 TTL 与失效重解析、冷门歌曲的查询扩展（P3）、人工补链出口（P3）、健康面板（P5）**。

## 1. 架构设计

### 1.1 分层

```text
┌──────────────────────────── 编排层（现有 pipeline） ────────────────────────────┐
│  离线解密失败 / 需联网 → FallbackCoordinator（新）                              │
└────────────────────────────────────────────────────────────────────────────────┘
                                     │
        ┌────────────────────────────┼────────────────────────────┐
        ▼                            ▼                            ▼
  QueryExpander               SearcherPool                  ManualLinkSource
  （查询扩展）                 （受控并发+限速+熔断+缓存）      （人工补链）
        │                            │
        │                    ┌───────┴────────┐
        │                    ▼                ▼
        │             SourceRegistry     MediaExtractor / PageResolver
        │             （声明式源清单）     （“模拟嗅探”：页面级媒体URL提取）
        │                    │                │
        └──────────► Fusion & Ranker ◄────────┘
                            │
                   ResourceIndex（sqlite3：去重 / 负缓存 / 健康统计）
                            │
                    Resolver（短 TTL 直链 + 失效重解析）
                            │
                 download → validate（现有校验）→ 写盘 + 打标签
```

### 1.2 与现有代码的关系（模块落点）

| 落点 | 处理 |
|---|---|
| `mmusic/search/` | 扩展：新增 `pack.py`（源清单模型）、`sniffer.py`（HTML/JSON-LD 提取）、`fusion.py`（归一化与打分）、`index.py`（sqlite 资源索引）、`health.py`（健康统计） |
| `mmusic/search/registry.py` | 改为从 **Source Pack** 构建，内置 4 源改造成 pack 条目（行为不变） |
| `mmusic/pipeline.py` | 只改 `_fallback()`：改为调用 `FallbackCoordinator`；**离线路径零改动** |
| `ui/` | 设置页增加“音源与健康度”面板、“礼貌模式”开关、“人工补链”入口 |
| `tests/` | 新增离线夹具与故障注入用例 |

### 1.3 源描述数据模型（Source Pack）

```jsonc
{
  "schema": 1,
  "pack_version": "2026.10.1",
  "min_app_version": "1.1.0",
  "sources": [
    {
      "id": "example_open_lib",
      "label": "公共领域音源示例",
      "kind": "json_api",              // json_api | html_scrape | template_url | local
      "enabled_by_default": false,     // 新增源默认关闭，需用户确认
      "license_note": "Public Domain / CC0",
      "homepage": "https://example.org",
      "search": {
        "url": "https://example.org/api/search?q={query}&limit={limit}",
        "headers": { "Referer": "https://example.org/" },
        "map": {                        // 响应字段 -> 统一字段（点路径）
          "title": "data.items[].name",
          "artist": "data.items[].artist.name",
          "page": "data.items[].permalink",
          "duration": "data.items[].length",
          "ext": "data.items[].format"
        }
      },
      "resolve": { "kind": "page_extract" },   // 从详情页提取媒体直链
      "quality": { "mp3": "320", "flac": "lossless" },
      "rate_limit": { "per_host_rps": 1.0, "burst": 3 }
    }
  ]
}
```

**为什么这样设计**：源是**数据**不是代码。新增/修复源 = 改一条 JSON；应用只认识上面有限的 `kind` 与 `map` 语义，因此远端下发的清单**无法执行任意代码**，从根上避免供应链风险。

### 1.4 四种声明式源类型

- **`json_api`**：公开 JSON 检索接口（现有酷狗/ aggregator 属此类）。
- **`html_scrape`**：检索页 → 详情页 → 媒体直链，两段式提取（“模拟嗅探”的载体）。
- **`template_url`**：已知的开放库直链模板（如公共领域音频库、用户自建静态站点）。
- **`local`**：本地曲库目录（离线优先，已有）。

## 2. 关键模块说明

### 2.1 SourceRegistry / PackLoader

- 启动时加载：内置 pack（随程序）→ 用户 pack（`%APPDATA%\MusicDecryptor\source_pack.json`）→ 可选远端 pack（默认关闭）。
- 校验：`schema` 版本、`min_app_version`、字段白名单、URL 必须是 `https`（`local` 除外）。
- 失效兜底：pack 解析失败 ⇒ 回退到内置 pack，**绝不因为清单损坏而启动失败**。

### 2.2 QueryExpander（查询扩展）

按代价从低到高生成变体，直到出结果：

1. 原样 `“标题 歌手”`
2. 去噪（复用现有 `clean_text`：去 `[mqms2]`/`(Live)`/`(Remaster)`/码率词）
3. 仅标题 / 仅歌手
4. 标题 + 时长约束（对“纯音乐版/翻唱”区分很有效）
5. 可选：CJK 拼音/罗马字变体（用**构建期生成的小型字表**，属数据，不构成运行时依赖）

每个变体带 `variant_reason`，最终报告里能看到“是靠哪个变体命中的”。

### 2.3 SearcherPool（受控并发）

- `concurrent.futures.ThreadPoolExecutor`，**全局上限 4**、**单 host 并发上限 1**。
- 每 host 一个**令牌桶**（默认 1 req/s，突发 3）+ 抖动退避；尊重 `Retry-After`。
- **熔断**：某源连续失败 N 次 → 隔离 10 分钟，期间不再请求，并在健康面板标记。
- **缓存**：同一进程内对 `(source, query)` 去重；跨进程用 `ResourceIndex` 的结果缓存（TTL 默认 6 小时）。
- **预算**：每文件最多 N 个候选、总耗时上限（默认 45 秒），到点即返回已得结果——保证不“卡住”。

### 2.4 MediaExtractor / PageResolver（“模拟资源嗅探”）

用标准库 `html.parser` + `json` + `re` 实现**页面级媒体提取**，不做无头浏览器：

- 结构化来源优先级：JSON-LD（`AudioObject.contentUrl` / `PodcastEpisode`）→ `og:audio` / `twitter:player:stream` → `<audio>/<source>/<video>` 的 `src` → `<script>` 内 JSON 里的 `https?://…\.(mp3|flac|m4a|ogg|wav)`
- 正则兜底：直接匹配媒体扩展名 URL，并**校验 Content-Type** 与文件头后才算命中。
- 明确边界：只读**公开返回的 HTML/JSON**；遇到登录墙/验证码页，识别特征后**直接放弃并记录**，不做绕过尝试。

### 2.5 Fusion & Ranker（打分已具备，补齐去重与低置信度）

统一打分**已由 v1.0.5 的 `match.py` 提供**（`rank_tracks_multi` + `split_originals`，含版本过滤与跨源择优），本节只补两件事：跨源结果的**去重**与**低置信度**处理。现有打分公式（供参考，不再改动）：

```
score = 0.55*相似度(标题) + 0.20*相似度(歌手) + 0.15*时长接近度 + 0.10*音质与格式偏好
      - 惩罚(低置信度来源 / 疑似直播或串烧 / 时长差异 > 30s)
```

- **低置信度阈值**：`score < 0.45` 的候选不自动下载，改为在结果里标注“低置信度”，GUI 让用户点选确认。
- **与版本过滤的关系**：被 `split_originals` 排除的伴奏/改编版不进主候选池；若整池为空，沿用现有提示（“未找到原曲，当前仅有伴奏/改编版…”），并把它作为**用户可选的次级池**，而不是直接失败。
- 排序后按序 resolve/download，**首个通过校验者胜出**（保留现有“下载即校验”的确定性）。

### 2.6 ResourceIndex（去重 / 负缓存 / 健康统计，`sqlite3`）

标准库 `sqlite3`，WAL 模式，单文件库放 `%APPDATA%\MusicDecryptor\resources.db`。

```sql
CREATE TABLE resource (
  key        TEXT,      -- 归一化(title|artist|duration_bucket)
  source     TEXT, url_hash TEXT, ext TEXT, bitrate INTEGER, size INTEGER,
  ok INTEGER, first_seen INTEGER, last_ok INTEGER, fail_count INTEGER,
  PRIMARY KEY (source, url_hash)
);
CREATE INDEX idx_key ON resource(key);
CREATE TABLE query_cache (q TEXT, source TEXT, payload TEXT, at INTEGER, PRIMARY KEY(q, source));
```

- **去重**：在现有打分之上再加一层内容去重（同一首歌在不同源可能重复命中）；`key = normalize(title)+"|"+normalize(artist)`，时长 ±2s 归桶；同 key 多源命中时按（已校验 > 码率 > 格式偏好 > 源优先级）选优；下载后可用**字节哈希**做二次确认（避免同名不同版）。
- **负缓存**：失败的 query 记 TTL，避免短时间反复撞同一个坏源（4xx 短 TTL，5xx 更短）。
- **健康统计**：每源的尝试/成功/平均延迟 → 供健康面板与自动排序。

### 2.7 Resolver（短 TTL + 失效重解析）

- **直链一律不长期缓存**：只在下一次下载前几秒内复用；TTL 默认 10 分钟。
- 下载遇 `403/404/410` ⇒ **重新 resolve 一次**；仍失败 ⇒ 记 `fail_count`、跳到下一候选/下一源。
- 与现有 `downloader.validate()` 直连：任何校验不通过都视为该候选失败，**不计入成功**。

### 2.8 SourceHealth 与面板

- `health.py` 汇总各源成功率/延迟/最近失败原因。
- GUI 设置页新增“音源与健康度”：显示顺序、开关、健康标记、可一键重排。
- 支持 CLI：`--sources-report`（JSON 输出，便于自动化）。

### 2.9 ManualLinkSource（人工补链 —— 网盘的“正确姿势”）

自动抓网盘既违反 ToS 也极易封；本方案改为**把网盘/任意直链交给用户本人**：

- GUI 失败条目上提供“手动补链”：粘贴直链或本地路径 → 复用现有 `download + validate + 打标签`。
- 也支持“从剪贴板批量导入链接”，按行解析，逐个校验与命名。
- 这样既满足“网盘资源也能用”，又把自动化风险与法律责任留在用户一侧（用户自己的链接、自己的账号）。

## 3. 数据流

```text
输入：无法解密 / 需联网的文件
  │
  ├─(1) 解析标题/歌手 + 时长（来自容器元数据或文件名）
  │
  ├─(2) QueryExpander 生成变体 v1..vn
  │        │
  │        └─► SearcherPool：多源并行检索（受控并发 + 令牌桶 + 熔断 + 缓存）
  │                 │  每个源内部：检索 → （html_scrape 时）详情页 → MediaExtractor 提取
  │                 ▼
  ├─(3) Fusion：归一化为统一 Track → ResourceIndex 去重 → 统一打分排序
  │
  ├─(4) 对 top-N 候选：Resolver（短 TTL）→ download → validate
  │        命中 ──► 写盘 + 打标签 + 记入 ResourceIndex（ok=1）
  │        失败 ──► 记 fail_count，尝试下一候选
  │
  └─(5) 全部失败：
           ├─► 输出可读结论 + “候选清单”（低置信度项也在内，供人工补链）
           └─► 负缓存 + 健康统计更新（下次更快、更少无效请求）
```

关键数据结构（新增，复用现有 `Track`）：

```python
@dataclass
class Candidate:
    track: Track
    source_id: str
    score: float
    reason: str            # 命中的查询变体 / 匹配依据
    low_confidence: bool   # score < 阈值，不自动下载
    page_url: str = ""     # html_scrape 时的详情页
```

## 4. 版权与合规护栏（硬性）

**准入规则（新增源必须满足）**

- 来源为公开且允许自动化访问的接口/页面；记录 `license_note` 与 `homepage`。
- 新增源进内置 pack 前需人工审核；用户 pack 里的源默认 `enabled_by_default: false`，需用户显式开启并确认“仅用于本人合法持有的资源”。

**运行时护栏**

- 只做**按歌曲名的定向检索**，不做全站遍历/批量枚举。
- 不提交登录态、不绕过验证码/付费墙；识别到登录墙即放弃。
- 尊重 `robots.txt` 与 `Retry-After`；内置**礼貌模式**（默认开）：更低并发与速率。
- 下载内容**必须通过文件头/码率校验**才落盘（复用现有 `validate`）。

**可追溯**

- `ResourceIndex` 保留来源与许可元数据；批次报告可导出（CSV/JSON），便于用户自查。

## 5. 实现步骤（分阶段，每阶段独立可交付）

- **P0 骨架（低风险，先行）**
  - 新增 `pack.py` + 改造 `registry.py`；把现有 4 个源**等价**迁移为 pack 条目（行为完全不变）。
  - 验收：现有 39 项自检 + `--check-ui` 全绿；新增“pack schema 校验”单元测试。
- **P1 融合与去重**
  - 新增 `fusion.py`、`index.py`（sqlite3）、负缓存。
  - 验收：多源重复用例只下一次；`_fallback` 改为统一打分后仍能通过既有集成测试。
- **P2 嗅探**
  - 新增 `sniffer.py`（`MediaExtractor` / `PageResolver`）；用**离线 HTML 夹具**测试。
  - 验收：夹具中 `og:audio`、JSON-LD、裸 `<audio>`、正则兜底四类各有用例；登录墙夹具必须“放弃而非绕过”。
- **P3 查询扩展与冷门覆盖**
  - `QueryExpander` + 低置信度标记 + 失败时的“候选清单 + 人工补链”出口。
  - 验收：给定的冷门/变体歌名集合命中率较 P0 提升（用固定响应夹具度量）。
- **P4 自更新（默认关闭）**
  - `PackLoader` 支持远端 pack：拉取 → 校验 sha256 → schema 校验 → 展示差异 → 用户确认后启用。
  - 验收：篡改哈希/超版本/字段越权三种情况都必须被拒绝并回退内置 pack。
- **P5 观感与观测**
  - 健康面板、`--sources-report`、批次覆盖率报告；把新增检查接入 `build.ps1` 门禁。

## 6. 测试策略

### 6.1 单元测试（全部离线，无网络）

- pack 解析与校验：合法 / 缺字段 / 越权 kind / 非 https / 版本不匹配。
- 查询扩展：变体生成与去噪（复用现有 `clean_text` 用例）。
- 打分与排序：给定候选集合，断言排序与低置信度划分。
- 去重：同 key 不同源/不同码率 → 只保留最优。
- `MediaExtractor`：四类结构化来源 + 正则兜底 + 登录墙识别（固定 HTML 夹具）。

### 6.2 故障注入（用桩替换 HTTP，不产生真实流量）

- `timeout` / `403` / `404` / `429 + Retry-After` / 返回 HTML 错误页 / 直链过期。
- 断言：正确重试、正确换源、熔断生效、**不崩溃且给出可读提示**、不把失败计入成功。

### 6.3 覆盖率度量

- 维护一个**歌名语料**（含冷门与变体）与**录制好的响应夹具**，离线跑完整链路，输出命中率。
- 作为 P3 的验收依据；语料持续追加（新增失败样本 → 先加夹具，再修。

### 6.4 回归门禁

- 现有：`tests/selftest.py`（39）、`tests/test_gui.py`、`tests/test_ui_fit.py`、`exe --check-qt`、`exe --check-ui`。
- 新增：**依赖守卫测试**——用 AST 扫描源码，断言运行时第三方 import 只允许 `PySide6` 与可选 `mutagen`（守住零依赖红线）。
- 新增：`--sources-report` 冒烟。

### 6.5 性能与礼貌性指标

- 单文件兜底总耗时上限（默认 45s）、单源并发上限、请求速率上限。
- 断言：受控参数生效；关闭网络时兜底路径快速失败而非长时间阻塞。

## 7. 边缘情况处理

- **链接临时失效**：直链短 TTL（10 分钟）+ 403/404 时**重新 resolve 一次** + 换源 + `fail_count` 记录；不把过期链接长期缓存。
- **多源重复资源去重**：归一化 `key`（标题|歌手|时长桶）+ 同 key 按（已校验 > 码率 > 格式 > 源优先级）选优；必要时用字节哈希二次确认，避免同名不同版被误判为重复。
- **冷门歌曲覆盖率低**：查询扩展（去噪/仅标题/拼音变体）+ 时长约束 + 放开低阈值并**标注低置信度交用户确认** + 最终“候选清单 + 人工补链”兜底；同时输出覆盖率统计，让“找不到”变成可量化、可改进的问题。
- **网盘限速 / 反爬**：不自动采集网盘；改为**用户自有链接的手工补链**（§2.9）。对可自动化来源则用令牌桶 + 熔断 + 礼貌模式，避免触发风控。
- **其它**：超大文件（> 200 MB）流式下载与大小上限；非 UTF-8 响应按 `Content-Type`/探测解码；同名冲突沿用现有 `(1)` 规则，绝不覆盖源文件。

---

## 8. 指标与验收

- **命中率**：固定语料上的兜底成功率（P0 基线 → P3 目标，按实测设定）。
- **无效请求率**：负缓存与熔断命中后，对坏源的重复请求应显著下降。
- **单文件兜底耗时**：P95 不超过设定预算。
- **稳定性**：新增代码不得引入任何崩溃路径；所有失败均为可读 `JobResult`。
- **红线**：运行时依赖仍为 `PySide6` + 可选 `mutagen`；exe 体积不显著增长。
